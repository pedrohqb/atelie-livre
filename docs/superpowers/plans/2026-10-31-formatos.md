# Ateliê Livre — Ferramentas de formato: plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Biblioteca Rust `formats` que lê todos os formatos de dados da pasta `MSKIDS` e binário `atelie-tools` que os inventaria e extrai para PNG/WAV/JSON, com documentação aberta dos formatos.

**Architecture:** Workspace Cargo com dois crates: `formats` (puro, só fatias de bytes, sem E/S) e `tools` (CLI que lê arquivos, chama `formats` e grava saídas). Cada formato é um módulo com uma função `parse`/`decode` sobre `&[u8]` que devolve `Result<_, FormatError>`. Formatos ainda não compreendidos (`PKBM`, `CHNK`) começam com uma etapa de investigação documentada antes do código.

**Tech Stack:** Rust 1.97 (edition 2024), `thiserror`, `clap` (derive), `png`, `serde` + `serde_json`.

**Spec:** `docs/superpowers/specs/2026-10-31-formatos-design.md`

## Global Constraints

- Licença GPL-3.0-or-later; campo `license = "GPL-3.0-or-later"` em todos os `Cargo.toml`.
- Edition 2024, `rust-version = "1.85"`.
- Sem `unsafe` (`#![forbid(unsafe_code)]` nos dois crates).
- `formats` não faz E/S de arquivo; depende só de `std` e `thiserror`.
- Nenhuma entrada malformada pode causar pânico, laço infinito ou alocação maior que o próprio arquivo: tamanhos declarados são confrontados com o tamanho real antes de alocar.
- Ordem de bytes sempre explícita na chamada (`u16_le`/`u16_be` etc.).
- Arquivos originais e saídas de extração nunca entram no repositório (`.gitignore` cobre `/target` e `/out*`).
- Nomes da Microsoft não aparecem em nomes de crate, binário ou variável; o binário é `atelie-tools`, a variável de dados é `ATELIE_DATA`.
- Testes com dados reais leem `ATELIE_DATA` (pasta `MSKIDS`); sem ela, imprimem aviso em stderr e retornam sem falhar. Nesta sessão: `ATELIE_DATA=/home/claude/fa_cw/MSKIDS`.

**Interfaces:**
- Consumes: `Reader`, `Format::Ne`, `ErrorKind`
- Produces:
  - `pub enum ResourceKind { Numeric(u16), Named(String) }` com `pub fn label(&self) -> String`: nomes padrão para 1..=16 (`CURSOR, BITMAP, ICON, MENU, DIALOG, STRING, FONTDIR, FONT, ACCELERATOR, RCDATA, MESSAGETABLE, GROUP_CURSOR, 13 → "#13", GROUP_ICON, 15 → "#15", VERSION`), outros numéricos `"#n"`, nomeados como estão.
  - `pub struct Resource<'a> { pub kind: ResourceKind, pub id: u16, pub name: Option<String>, pub data: &'a [u8] }` — `id` com o bit 0x8000 limpo quando o id é numérico; `name` preenchido quando o id é por nome (então `id` = 0).
  - `pub struct NeFile<'a> { pub modules: Vec<String>, pub resources: Vec<Resource<'a>> }`
  - `pub fn parse(data: &'a [u8]) -> Result<NeFile<'a>>`
  - `impl NeFile { pub fn of_kind<'s>(&'s self, label: &'s str) -> impl Iterator<Item = &'s Resource<'a>>; pub fn find(&self, label: &str, id: u16) -> Option<&Resource<'a>> }`

Layout NE (todos little-endian): `MZ` em 0; `u32` em 0x3C = offset do cabeçalho `NE`. No cabeçalho: `u16` em +0x1E = nº de módulos importados; `u16` em +0x24 = offset (relativo ao cabeçalho) da tabela de recursos; +0x28 = tabela de referência de módulos; +0x2A = tabela de nomes importados. Tabela de recursos: `u16` shift de alinhamento; depois blocos `{u16 type_id; u16 count; u32 reservado; count × {u16 offset; u16 length; u16 flags; u16 id; u32 reservado}}` até `type_id == 0`. Offset e length em bytes = valor << shift. Se o bit 0x8000 está ausente em `type_id` ou `id`, o valor é offset (relativo ao início da tabela de recursos) de uma string Pascal. `data` inclui o preenchimento de alinhamento — consumidores usam seus próprios campos de tamanho. Recurso que ultrapassa o fim do arquivo → `FormatError`.

### Task 6: Sons RIFF/WAVE com ADPCM da Microsoft

**Files:**
- Create: `crates/formats/src/wave.rs`, `docs/formats/sons.md`
- Test: unitários em `wave.rs`; integração em `crates/formats/tests/real_ne.rs`

**Interfaces:**
- Consumes: `Reader`, `Format::Wave`, `ne::parse`
- Produces:
  - `pub struct Pcm { pub sample_rate: u32, pub channels: u16, pub samples: Vec<i16> }` — intercalado
  - `wave::is_riff_wave(data: &[u8]) -> bool`
  - `wave::decode(data: &[u8]) -> Result<Pcm>` — formatos 1 (PCM 8 e 16 bits; 8 bits é sem sinal, converter com `(b as i16 - 128) << 8`) e 2 (MS ADPCM, 1 ou 2 canais); outros → `Unsupported`
  - `wave::encode_pcm16(pcm: &Pcm) -> Vec<u8>` — WAV PCM 16 bits (usado pelo `tools`)

Usa o tamanho do RIFF, não o do recurso (o recurso NE tem preenchimento). Chunks desconhecidos são pulados (tamanho ímpar → +1 byte de preenchimento). MS ADPCM: coeficientes lidos da extensão do `fmt ` (`u16` cbSize, `u16` samplesPerBlock, `u16` numCoef, numCoef × (`i16`, `i16`)); tabela de adaptação `[230, 230, 230, 230, 307, 409, 512, 614, 768, 614, 512, 409, 307, 230, 230, 230]`; cabeçalho do bloco por canal: preditor `u8`, delta `i16`, amostra1 `i16`, amostra2 `i16`; saída começa com amostra2, amostra1; nibbles com o mais alto primeiro; previsão `(s1·c1 + s2·c2) >> 8`, mais `nibble_com_sinal × delta`, saturado em i16; novo delta `(adapt[nibble] × delta) >> 8`, mínimo 16. Último bloco pode ser parcial: decodificar só os bytes presentes. Se houver chunk `fact`, truncar ao número de amostras dele. Índice de preditor ≥ numCoef → `Invalid`.
